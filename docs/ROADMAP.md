# 业务功能路线图

## 产品目标

让个人开发者在终端里完成“理解项目 → 制定小任务 → 修改文件 → 跑测试 → 检查结果 → 下次继续”，同时让 Go 应用能按需嵌入 Agent 核心。

优先衡量任务是否可靠结束、用户能否看到过程和恢复现场。dsh 的可组合能力、日志可追溯性、长任务管理和模块契约是借鉴方向，依据见 [对比分析](analysis/deepseek-harness-vs-basework.md)。

## 用户场景与分期

| 阶段 | 用户得到什么 | 交付边界 | 任务组 |
|---|---|---|---|
| M0 基线与文档 | 能看懂现状，知道下一项交给 AI 做什么 | 文档集中、任务入口、可重跑基线 | DOC / BASE |
| M1 可靠模型调用 | 换模型后仍能正确读文件、调用工具、处理失败 | 协议回归、能力来源、真实编码闭环、请求审计策略 | REL |
| M2 长命令 | 跑测试/构建时可继续观察、读取输出和取消 | owner 隔离、输出限额、进程清理、重启后事实恢复 | JOB |
| M3 可靠编辑 | 知道准备改哪里，文件被别人改动时不会覆盖 | 预览、冲突检测、批量提交、受保护撤销 | EDIT |
| M4 配置体验 | 知道当前配置从哪里来，切换使用场景更简单 | 脱敏配置解释、启动预设、可回收扩展资源 | CFG |
| M5 项目记忆 | 下次打开还能知道读过、改过、运行过什么 | 结构化事实、预算内摘要、来源与过期检测 | CTX |
| M6 运行服务边界 | CLI/TUI 使用同一套运行、取消、会话事件 | 先完成进程内服务接口；远程协议延后 | RUN |
| M7 可见的终端体验 | 工具、权限、编辑和任务状态在同一处呈现 | 状态卡片、权限/编辑确认、切换会话不串流 | UI |
| M8 可交付版本 | 按文档安装，完成代表性任务，有可追溯验证 | 回归场景集、干净安装、正式发布前人工验收 | SHIP |

任务依赖以 [看板](TASKS.md) 为准：M2/M3 可在基线后独立推进；M5 依赖命令与编辑事件；M7 依赖服务事件与编辑预览。不要求一个 AI 同时推进多组。

## 业务验收场景

| 场景 | 输入 | 用户可观察的成功结果 |
|---|---|---|
| 修复一个缺陷 | 给出可复现错误和测试项目 | 展示涉及文件、修改前后差异、测试结果；失败有可操作说明 |
| 执行耗时检查 | 运行耗时测试/构建 | 命令状态与输出持续可见，取消后子进程退出，结果可回看 |
| 中断后继续 | 退出并重新打开同一项目会话 | 恢复事实与摘要；已终止任务不会显示仍在运行，不会自动重跑有副作用命令 |
| 使用不同模型 | 选择支持工具的模型 | 能力来源明确；缺密钥或不支持工具时明确告知，不静默关闭工具 |
| 嵌入 Go 服务 | 宿主注入模型、工具、会话与权限 | 不引入终端依赖，关闭能清理资源，原公开接口保持兼容 |

上述是持续验收要求。2026-09-14 复审确认部分组件已实现，但运行接线、恢复与交互仍有缺口；在重新验收前优先修已有闭环。问题与依据见 [复审报告](development/evidence/REVIEW-2026-09-14.md)，具体小步骤在原任务卡维护。

## 复审后的工作顺序

先修撤销权限/路径、服务关闭与日志恢复，再接通主运行选项、事实摘要及旧会话继续；随后验收 TUI 分页/审批/切换和目标平台产物。新增 QA-001 固化验收夹具；M9 的 OPT-001/002 改善非交互初始化和性能测量，优先级低于现有缺陷。持续状态以 [看板](TASKS.md) 为准。

## 后续候选方向与进入条件

| 方向 | 进入条件 | 暂缓理由 |
|---|---|---|
| 工作流与任务依赖图 | 单任务取消/恢复与事件语义稳定；重复业务流程有真实样本 | 避免在不稳定单任务上扩展编排 |
| 远程 server / 多客户端 | M6 接口完成，明确认证、隔离、协议兼容和远程访问需求 | 当前先解决单机 CLI/TUI 一致性 |
| OS 沙箱 | 有明确的运行环境、威胁模型和平台维护预算 | 权限策略与实际隔离应分别设计、分别验收 |
| Web / 桌面 / IDE 客户端 | 核心任务体验与服务接口稳定，有具体用户需求 | 避免维护多个未完成的界面 |
| Homebrew 分发 | 安装与升级验证完成，有维护 tap 的责任人 | 当前安装入口不应承诺未接入渠道 |
| 第三方插件市场 | 可回收注册、版本兼容与安装信任边界稳定 | 不直接移植 Cordis 或拆成大量细包 |

候选方向不纳入当前完成率，也不在用户未选择前自动开工。旧 Phase 36 的映射：36.1→REL，36.2→JOB，36.3→EDIT，36.4→CTX，36.5→RUN，36.6→UI；Phase 37 已有能力归入 STATUS，不重复建造。

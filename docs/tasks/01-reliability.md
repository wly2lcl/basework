## REL-001：流式工具调用协议回归

**前置任务**：BASE-001。依赖尚未完成时，只能调查或细化方案，不能宣称本项已验收。

**先读 / 主要修改范围**：`pkg/provider/`、`pkg/llm/`、`pkg/agent/pipeline.go`。首次阅读应确认实际文件/符号，拟新增路径不存在属正常。

**实施步骤**：

1. 阅读流式事件与参数累积实现。
2. 用现有测试框架重放增量参数、最终完整参数、交错调用与空文本。
3. 只修复可复现的不一致并明确归一化归属。
4. 验证取消、断流和重试不会重复执行工具。

**验收条件**：

- 参数不丢失也不重复拼接。
- tool call ID 与结果对应。
- 失败/重试不会隐式重复有副作用的执行。

**针对性验证**：go test ./pkg/provider ./pkg/agent ./pkg/llm -count=1。命令均从仓库根执行；必须记录结果和覆盖边界。

**交付与回填**：代码/文档 diff、必要测试，以及 `docs/development/evidence/REL-001.md`。更新看板的状态和证据；有用户可见行为变化时更新对应指南及 STATUS。

**范围外**：不顺手改其他任务；公共 API、存储格式、默认权限的额外变化必须先写明影响并拆分。

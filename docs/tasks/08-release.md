# M8：评估与发布准备

状态只在 [任务看板](../TASKS.md) 更新。执行前读 [AI 开发流程](../development/ai-workflow.md)。下面是实施范围，新增名称均为拟定；发现已有实现先验证缺口。每张卡可分多个小提交，但验收全部满足后才算完成。

<a id="ship-001"></a>

## SHIP-001：固定编码场景回归集

**前置任务**：REL-003, CTX-003。依赖尚未完成时，只能调查或细化方案，不能宣称本项已验收。

**先读 / 主要修改范围**：`tests/`、`docs/development/evidence/`。首次阅读应确认实际文件/符号，拟新增路径不存在属正常。

**实施步骤**：

1. 建立小函数修复、多文件修改、大输出、权限拒绝、断流恢复样例。
2. 固定输入/测试断言和产物而非模型文案。
3. 离线重放覆盖可确定逻辑，真实模型结果另存。
4. 记录成功率、耗时、调用量及失败类型。

**验收条件**：

- 每个场景可重复运行且清理独立。
- 不把一次成功当稳定成功率。
- 费用未知明确标未知，不能由 token 数编造账单。

**针对性验证**：go test -tags "sqlite memory" ./tests -count=1；真实场景按 validation.md 执行。命令均从仓库根执行；必须记录结果和覆盖边界。

**交付与回填**：代码/文档 diff、必要测试，以及 `docs/development/evidence/SHIP-001.md`。更新看板的状态和证据；有用户可见行为变化时更新对应指南及 STATUS。

**范围外**：不顺手改其他任务；公共 API、存储格式、默认权限的额外变化必须先写明影响并拆分。

## SHIP-002：跨平台安装与升级验证

**前置任务**：SHIP-001, UI-003, CFG-002。依赖尚未完成时，只能调查或细化方案，不能宣称本项已验收。

**先读 / 主要修改范围**：`docs/installation.md`、`docs/release.md`、`.goreleaser.yml`、`.github/workflows/`。首次阅读应确认实际文件/符号，拟新增路径不存在属正常。

**实施步骤**：

1. 在隔离目录或干净机器验证承诺的平台产物。
2. 验证初次配置、旧版本会话升级与未知高版本拒绝。
3. 执行打包 dry-run 且核对产物文档。
4. 记录系统、产物哈希与缺失平台。

**验收条件**：

- 不能用本机交叉编译冒充目标系统运行。
- 安装说明只包含已接入渠道。
- 升级不破坏原用户数据且有可执行恢复说明。

**针对性验证**：CI 平台测试/构建及 release dry-run；各承诺目标平台实际安装证据。命令均从仓库根执行；必须记录结果和覆盖边界。

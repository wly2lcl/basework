## DOC-001：文档集中与可执行任务体系

**前置任务**：—。依赖尚未完成时，只能调查或细化方案，不能宣称本项已验收。

**先读 / 主要修改范围**：`docs/`、`scripts/doccheck/`、`Makefile`。首次阅读应确认实际文件/符号，拟新增路径不存在属正常。

**实施步骤**：

1. 迁移正文到 docs 并修复链接。
2. 归档旧 Phase 与过时分析。
3. 建立路线图、任务卡、状态规则。
4. 适配文档检查和进度统计。

**验收条件**：

- 根目录仅 README 导航。
- 每个现有 pkg 包都有集中契约。
- 看板任务引用、依赖和完成证据可检查。

**针对性验证**：make check-docs && make progress。命令均从仓库根执行；必须记录结果和覆盖边界。

**交付与回填**：代码/文档 diff、必要测试，以及 `docs/development/evidence/DOC-001.md`。更新看板的状态和证据；有用户可见行为变化时更新对应指南及 STATUS。

**范围外**：不顺手改其他任务；公共 API、存储格式、默认权限的额外变化必须先写明影响并拆分。

## BASE-001：建立可复跑的当前基线

**前置任务**：DOC-001。依赖尚未完成时，只能调查或细化方案，不能宣称本项已验收。

**先读 / 主要修改范围**：`pkg/`、`internal/`、`cmd/basework/`、`tests/`、`.github/workflows/build.yml`。首次阅读应确认实际文件/符号，拟新增路径不存在属正常。

**实施步骤**：

1. 记录 HEAD 与未提交范围、Go 版本和系统。
2. 运行默认与完整构建测试。
3. 将失败分为代码、环境、外部服务三类并保留原始摘要。
4. 核对 STATUS 并登记可复跑基线。

- 两个构建模式结果明确。

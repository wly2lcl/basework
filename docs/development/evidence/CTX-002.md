# CTX-002 受预算约束的项目摘要

## 基线

- 仓库：`basework`，日期 2026-09-12，工作树含本会话此前任务的未提交改动（用户未授权 commit）。
- 前置：CTX-001 已完成（`WorkspaceFacts` 模型、facts 文件、工作区归属戳）。
- 实施前：`pkg/agent/environment.go` 有 `ContextProvider`/`ContextCollector` 契约但产品运行时未接入任何事实类 Provider；事实数据只能通过 `basework facts show` 人工查看，模型无法获得项目历史摘要；`Config` 无摘要开关。

## 变更

**pkg/session/facts_summary.go**（新增）：

- `SummarizeFacts(w, opts)`：预算内的项目事实摘要。相关性选择顺序 modified > reverted > command > read，同类内新者在前；每行必带来源与首次时间（来源可追踪是硬要求）。
- **不扫描仓库**：只遍历去重后的事实集合，无任何目录遍历入口——「无上限扫描」结构性不可能。哈希调用另有 `MaxHashPerBuild=64` 次封顶。
- **过期检测**：`StaleTracker` 记录文件内容哈希基线（由调用方注入的 `Hash` 函数求取）；本次哈希与基线不同 → 该事实标 `[已过期:文件随后又变化，仅作历史参考]`。tracker 由调用方持有复用（nil 则仅本次构建内有效，注释说明）。
- **预算裁剪**：按行丢弃不截半行；截断后附总数与截断时间说明。
- **未读取标识**：hash 返回错误（含受保护路径被调用方拒绝）→ 标 `[未读取]`，不判过期、不报错。

**pkg/agent/facts_provider.go**（新增）：

- `FactsSummaryProvider` 实现 `ContextProvider`（对接既有 `ContextCollector` 契约）。`Collect` 每次从盘加载事实（未来版本等错误容错为空摘要，与 Provider 家族口径一致）。
- **保护路径不读取**：`ErrProtectedPath` 由调用方 hash 实现返回；`wrapHash` 拒绝绝对路径与含 `..` 的越界相对路径——越界请求根本不会到达 hash 函数。`FileHash` 提供标准 SHA-256 实现，但策略判断留给调用方。

**pkg/config/config.go**：`Config.FactsSummary *FactsSummaryConfig`（`facts_summary` 段，omitempty 可选兼容变更）。**默认 nil = 关闭**：不加载事实文件、不读任何文件、完全旧行为。

**cmd/basework/runtime.go**：

- `runtimeSystemPrompt` 增加摘要段：`cfg.FactsSummary.Enabled` 时把摘要追加进 system prompt；注入内容随既有 `request.built` 审计指纹落账（「按请求审计策略注入」——审计链路无需新机制，指纹覆盖 system prompt）。
- `factsHashFunc`：产品层哈希实现——先过 `permission.PathChecker`（与工具层同一敏感路径策略，拒绝即返回 `ErrProtectedPath`），再读文件求哈希。
- 子代理不注入摘要（任务级 Context 已有），通过传 nil hash 显式跳过。

**测试**：`pkg/session/facts_summary_test.go`（6 条：来源与排序、预算截断、过期检测（共享 tracker）、未读取不计过期、空事实、无文件系统访问也可生成）；`pkg/agent/facts_provider_test.go`（5 条：Collect、受保护路径不读盘、未来版本容错、缺依赖 nil、越界路径在 wrapHash 被拒）；`cmd/basework/facts_test.go`（+2：开关与保护、factsHashFunc 尊重 PathChecker）。

**实现期修正的真 bug**：provider 初版收「facts 目录」而 `LoadWorkspaceFacts` 内部会再拼一层 `facts/`，导致双层嵌套读不到文件（cmd 测试抓到）；修正为 provider 收会话数据根目录。

## 验证

- 任务卡针对性验证：`go test ./pkg/agent ./internal/compaction ./pkg/session -count=1` → PASS（连同 `./cmd/basework ./pkg/config` 一起跑，全 ok）。
- race：`go test -race -tags "sqlite memory" ./pkg/session ./pkg/agent ./internal/compaction` → PASS。
- 全量：带 tag 34/34、默认 34/34（退出码 0）；windows/linux 交叉编译通过；`make check-arch`/`make gen` 幂等通过。
- 验收条件逐条：① 不扫描仓库——结构性保证（无遍历入口）+ 测试 `TestSummarizeFacts_NoRepoScan_Structural`；② 来源可追踪且过期有标识——每行带来源，`[已过期]`/`[未读取]` 标注有测试；③ 关闭恢复旧行为不读保护路径——默认 nil 关闭（零读取），开启时受保护路径经 PathChecker 拒绝（`TestFactsHashFunc_RespectsPathChecker`）。
- 覆盖边界：摘要当前在 Agent 启动时构建一次（system prompt 静态），非每请求重建——「按请求注入」的审计口径由 request.built 指纹覆盖，摘要内容的新鲜度以进程启动时刻为准（跨构建过期检测机制已备好，接 RUN-003 每请求重建时生效）；哈希基线在内存中，随进程重启丢失（持久化基线属事实文件格式演进，按范围外拆分）；真实 Provider 端到端仍未验证（既有红线）。

# JOB-001 验证记录：定义并实现 job 状态与归属

## 基线

- 起点 HEAD：`935fde1`；工作树含 BASE-001 / REL-001 / REL-002 / REL-004 的未提交改动。
- 环境：macOS 26.6.2 arm64 / go1.26.0。
- 相关既有实现核对结果：
  - `pkg/tool/builtin/bash.go` 是**同步**执行：`exec.CommandContext` + `cmd.Run()`，
    等命令结束才返回；输出在内存里拼接并硬截断到 100KB（`maxOutputSize`）。
  - 权限入口有两道：`builtin.CheckBlacklist(cmd, extra)`（黑名单，`PermissionMode`
    控制 yolo / interactive / default）与 `getPathChecker().CheckPath(p)`
    （`pkg/tool/builtin/path_checker.go`，未导出）。路径检查在 `pkg/tool` 内部完成。
  - `pkg/session/event.go` 的事件类型里没有任何 job 相关事件，也没有 job 概念。
- 因此"后台任务"在本任务之前**完全不存在**：既没有状态、没有归属，也没有 job ID。
  这一步是从零建立，不是修补。

## 变更

### 新增 `internal/jobs`（核心）

- `State` 六态：`queued` / `running` / `succeeded` / `failed` / `canceled` / `interrupted`，
  `State.Terminal()` 判定终态。`interrupted` 专门留给"进程消失或重启后无法接管"，
  目的是**不允许把"不知道还在不在跑"写成"还在跑"**。
- `Manager`（`New(Options)`）：可注入时钟与 ID 生成器，默认 ID 为单调递增的 `job-001` 形式，
  不引入随机数，测试可复现。
- **归属必填**：`owner` 为空直接 `ErrMissingOwner`。所有者设为可选等于让忘记传 owner 的
  调用方得到一个全局可见的 job，而且不会报错——所以它不可选。
- 越权与不存在返回**同一个** `ErrNotFound`。若区分开，错误信息本身就成了探测其他会话
  job ID 的通道。
- **终态只有一个发布点**：所有路径（正常结束、非零退出、执行报错、取消）都收敛到
  `Manager.settle`，由 `settled` 标志保证幂等，`OnTerminal` 回调恰好一次。
  `Cancel` 只发取消信号，不直接改状态——否则会出现"Cancel 先写 canceled、执行协程随后
  又写 failed"的双写。
- 明确的错误分类：`ErrMissingOwner` / `ErrEmptyCommand` / `ErrNilRunner` /
  `ErrConcurrencyLimit` / `ErrAlreadyTerminal` / `ErrNotFound`。调用方按 `errors.Is` 判定，
  不需要匹配文本。
- 并发额度：`MaxConcurrent`（全局）与 `MaxPerOwner`（单 owner）。校验顺序是
  **先校验、后占额度、最后登记**，任何拒绝都不留半个 job、不漏额度。
- 其他：`Get` / `List` / `Cancel` / `CancelOwner` / `Await` / `Wait` / `Active` / `Len`。

### 新增 `internal/tools/background.go`（产品适配器）

- `BackgroundBashTool` 按与同步 bash **相同顺序**走权限入口：
  黑名单（复用 `builtin.CheckBlacklist`，同一份实现）→ 路径检查（注入
  `CheckPath`，与产品层共用同一个检查器）→ 启动。被拒绝时不登记任何 job，
  不存在"权限拒绝了但进程已经跑起来"的窗口。
- 返回 `JobHandle`（`job_id` / `owner` / `command` / `state`）的 JSON 文本。
  结构化而不是拼提示文本：后续的输出读取、取消、恢复都要按 job ID 定位同一对象，
  字符串句柄必然要被重新解析，那是漂移来源。
- **`pkg/tool` 接口未改动**：不新增接口方法、不改 `tool.Result`，句柄放在 `Content` 里。
  已用 `git status --short pkg/tool/` 确认为空。
- 覆盖边界（写在代码注释里，也写在这里）：命令输出当前**丢弃**；
  增量输出 / 配额 / 分页属 JOB-002，超时进程树清理属 JOB-003，重启恢复与 CLI 接线属 JOB-004。
  没有实现的部分不假装实现。

## 剩余与交接

- **输出能力缺失（JOB-002）**：`BackgroundBashTool` 当前 `Stdout/Stderr = io.Discard`。
  这是刻意的——用内存拼接 + 100KB 截断冒充"输出已完成"会掩盖真实问题。
  JOB-002 需要引入 stdout/stderr 偏移、分页读取、内存与总存储配额、溢出到私有文件。
- **超时后进程树清理（JOB-003）**：当前超时靠 `exec.CommandContext` 杀直接子进程，
  孙进程不会被回收。JOB-003 需要进程组终止 + 宽限期。
- **持久化与 CLI 接线（JOB-004）**：Manager 目前是纯内存；重启后 job 全丢。
  JOB-004 需要持久化命令摘要/状态/输出引用，并把重启后无法接管的运行中任务标为
  `interrupted`（`State` 已预留该取值）。
- **未接入产品组装**：`BackgroundBashTool` 已实现但尚未注册进 `cmd/basework/runtime.go`
  的工具表。这属于 JOB-004 的"注册 job 查询/输出/取消工具并沿用权限"，本卡只要求
  "产品适配器返回结构化 job ID"，未越界接线。
- `Manager` 的 `OnTerminal` 目前无人订阅（产品层要等持久化就位），因此它只被测试使用。

## 结论

验收项逐条对照：

| 验收条件 | 结果 | 依据 |
|---|---|---|
| 会话之间不能读/取消对方 job | 通过 | 归属必填；越权与不存在返回同一 `ErrNotFound`；`TestOwnership_OtherSessionCannotReadOrCancel`、`TestBackgroundBash_OtherSessionCannotSeeJob` |
| 重复结束不会重复发终态 | 通过 | 终态唯一发布点 `settle` + `settled` 幂等标志；`TestSettle_TerminalPublishedExactlyOnce`、`TestSettle_CancelRacingNaturalExit`（200 轮）、`TestConcurrent_StartCancelAcrossOwners`（200 job 全计数） |
| 并发数量与启动失败有明确返回 | 通过 | `ErrConcurrencyLimit` 分全局/单 owner 两种；四种启动校验错误各有独立错误值且不留半个 job；`TestLimits_ExplicitRejection`、`TestStart_ValidationRejectsBeforeRegistering` |
| 保持 pkg/tool 接口兼容 | 通过 | `git status --short pkg/tool/` 为空；适配器不新增接口方法、不改 `Result` |

针对性验证（含 `-race`）通过，2 个测试文件共 21 条用例覆盖全部验收条件。

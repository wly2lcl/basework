## 验证

- race：`go test -tags "sqlite memory" -race ./pkg/session ./pkg/agent -count=1` → ok。
- 全量门禁：双模式 34/34 包 ok（退出码 0）；`GOOS=windows`/`GOOS=linux` 编译通过；`make check-arch` 通过；`make gen` 幂等。
- 人工重启验证（真实二进制 + 隔离 HOME，`/private/tmp/ctx003/`）：
  - 进程 1 遗留：非终态 job 记录（running）+ 含压缩快照/失败工具调用/文件冲突的会话事件；
  - 进程 2 `basework jobs list`：只读展示并提示「重启 Agent 会归并为 interrupted」——归并本身刻意只在 Agent 启动路径执行（`ReconcileOwner`，JOB-004 的 `TestRestartReconcile` 单测覆盖），查看命令不产生副作用；
  - 投影核对程序：重启后快照历史（`修复 a.go 的冲突`）、失败原因（`提交失败：文件冲突`）、文件冲突记录（`conflict`）三者均在。
- **日志体积增量（任务卡第 5 步）**：`TestRestart_SnapshotSizeDelta` 实测——同一段约 2100 字节的消息负载，旧格式压缩事件 68 字节（只存锚点），快照事件 2432 字节（存完整消息，约 35 倍）。这是「精确恢复」对「单锚点近似」的已知代价：换掉的是截断锚点无法表达的选择、删除与重排能力。
- Steering 累积行为与上下文增长：`TestBuildRequestMessages_RestartAfterCompactions` 验证全部已持久化 steering 在后续请求中重放（2 轮都在、按序）；其上下文增长为每轮注入一条 system 角色消息（`steeringToChatMessages`），随历史持久化、跨重启保留，不会因压缩丢失（steering 事件不参与投影压缩，独立回填）。

# UI-001：工具与后台任务状态卡片

## 基线

- 前置 RUN-003 已完成：TUI 订阅运行事件（RunEventMsg 带 RunID/SessionID），工具开始/结束已经由 ToolStartMsg/ToolEndMsg 投递（失败带 IsError + 错误文本）。
- 改造前缺口：后台任务在 TUI 中完全不可见（无列表、无输出、无取消入口）；运行终态（完成/取消/失败）无通知；`RunEventMsg` 只做路由记录。

## 变更

- **`internal/tui/jobs.go`（新增）**：`JobsView` 状态卡片组件——
  - `JobStatus.StateLabel()`：queued/running/succeeded/failed/canceled/timed_out/interrupted → `[排队]/[运行中]/[成功]/[失败(退出码 N)]/[已取消]/[超时]/[已中断]`，**文字标记硬要求**（不依赖颜色）；
  - 列表封顶 `jobsListMax=50`；输出按页读取（每页 30 行 / 8KB 上限），渲染再按页大小截断——大输出不卡死渲染与输入；
  - 按键：`enter/o` 加载输出、`]`/`[` 翻页、`x` 取消（终态任务拒绝并提示）、`esc` 关闭；操作反馈走 `notice` 一行文本；
  - `SetRuntime(reader, cancel)` 由 cmd 侧注入读取/取消能力（绑定归属后），组件不直接触碰 job 管理器。
- **`internal/tui/app.go`**：
  - `App.Jobs` 字段 + `SetJobsRuntime` 注入口；
  - `Update` 新增 `JobStatusMsg` 分支（全量替换快照）；`RunEventMsg` 的 finished 终态产出文字通知：`[运行完成]`/`[运行已取消]`（系统通知）与 `[运行失败]`（错误样式）；
  - 卡片可见时按键优先被 `JobsView.HandleKey` 消费；`ctrl+j` 切换（keymap 新增 `ActionToggleJobs` + 描述「后台任务卡片」）；View 渲染叠加卡片。
- **`internal/tui/keymap/keymap.go`**：`ActionToggleJobs`（`ctrl+j`，全局层）+ 中文描述。
- **`cmd/basework/tui.go`**：`readJobOutputPage`（封装归属 + ReadOutput stdout 分页）、`mergedJobStatuses`（内存态与持久化历史合并、内存优先，与 job_list 工具同口径）；`runTUI` 增 500ms 快照轮询 goroutine，`defer close(stopPoll)` 覆盖全部退出路径。

## 验证

- 新增测试 7 条（`internal/tui/jobs_test.go`），全部通过：
  - `TestJobStatus_StateLabelHasTextMarker`（七种状态文字标记）；
  - `TestJobsView_LargeOutputTruncated`（600KB 输出渲染行数被限制在页大小内 + 续读提示）；
  - `TestJobsView_CancelTerminalRefusedAndRunningRequested`（终态拒绝取消、运行中发出请求）；
  - `TestJobsView_Pagination`（翻页/末页提示/回退不低于 0）；
  - `TestJobsView_ListCapped`（列表封顶 50）；
  - `TestApp_Update_JobStatusMsgAndRunCancelNotice`（卡片数据更新、取消/失败通知可见）；
  - `TestJobsView_NarrowWindow`（宽度 20 渲染不 panic、单行 rune 数受控）。
- 任务卡针对性验证：`go test -race ./internal/tui ./cmd/basework ./internal/runtime -count=1` → 3 包 ok。
- 全量门禁：双模式 34/34 包 ok（退出码 0）；`GOOS=windows`/`GOOS=linux` 编译通过；`make check-arch` 通过；`make gen` 幂等；`gofmt -l` 干净。
- 人工验证的覆盖边界：**全屏 TUI 的真实按键操作需要 TTY**，沙箱内无法实测（`ctrl+j` 打开卡片、方向键选择、x 取消的真实击键序列未在终端人工执行）；覆盖方式为 App.Update/HandleKey 层的按键处理单测 + 窄窗渲染测试。真实 TTY 下的人工操作留待 SHIP-001 固定场景回归时一并执行。

## 剩余与交接

- 工具执行的中间进度（如运行中的输出增量）当前只有工具名与结束结果，流式输出增量走原有 StreamingView（不在本卡片）。
- 卡片轮询间隔 500ms 固定值；如需可配置属后续小改动。
- 快捷键说明已写入卡片标题行（ctrl+j 关闭 · enter/o 查看输出 · [ ] 翻页 · x 取消）。

## 结论

UI-001 验收条件逐项满足：工具开始/结束/失败可见（既有消息流 + 错误样式）、取消可见（运行取消通知 + 任务卡片 x 键）；大输出不卡死（分页读取 + 渲染行数/字节双上限）；颜色之外有文字区分（全部状态带 `[文字]` 标记）。任务完成。

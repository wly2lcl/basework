# OPT-001 验证记录：非交互初始化

## 基线

实现位置：`cmd/basework/onboard.go`；测试：`cmd/basework/onboard_test.go`。原入口在 stdin 打开但无输入时会等待，AI/脚本流程缺少确定终态。

## 变更

新增 `basework init --yes`，并支持 `--provider`、`--model`、`--preset` 与显式 `--force`。无人值守路径不读取 stdin；默认 provider/model 可确定生成（无 key 时沿用 OpenCode 免费模型路径），需要 key 的 provider 缺 key 直接返回非零错误。已有配置默认保留，覆盖必须显式 `--force`；密钥只从环境读取，不写入配置和输出。

## 验证

- `go test ./cmd/basework -run 'TestRunInitNonInteractive' -count=1`：通过。
- 隔离 HOME 的真实二进制 `init --yes --provider opencode --preset readonly`：退出码 0，生成 `provider=opencode`、`model=big-pickle`、`preset=readonly`。
- 同一隔离 HOME 再次运行 `init --yes --provider opencode --model changed`：退出码 0，文件字节保持不变。
- 全新隔离 HOME 运行 `init --yes --provider openai` 且未设置 `OPENAI_API_KEY`：退出码 1，输出明确要求设置 `OPENAI_API_KEY`。
- 原交互入口未移除；非交互路径与交互路径分支隔离，旧配置加载与保存逻辑保持。
- 新增边界测试并通过：EOF 下交互入口仍确定生成默认配置；异常 provider/model 输入回退稳定默认值；
  `--yes` 在保持打开且无数据的 stdin 管道下 2 秒内返回，证明无人值守路径没有读取 stdin。
- 复跑 `go test -count=1 ./cmd/basework` 与
  `go test -race -tags 'sqlite memory' -count=1 ./cmd/basework`，均通过。
- `PYTHONDONTWRITEBYTECODE=1 python3 tests/opt_pty_init.py` 在真实 PTY 中完成 provider
  选择、空 key、免费模型选择和配置写入，输出 `OPT-001 PTY acceptance passed`。
- `.github/workflows/build.yml` 的 Quality job 已加入同一条 PTY smoke；候选 CI 运行后可
  直接回填该步骤结果。

## 剩余与交接

真实 PTY 交互已验证；尚未在 Windows runner 做独立 TTY 录入，该边界仍属于跨平台发布
验收，不把本机 PTY 结果扩大解释为 Windows 终端体验。

## 结论

非交互初始化的本机实现和隔离 HOME 验证完成；交互兼容与跨平台 TTY 仍由发布任务继续覆盖。

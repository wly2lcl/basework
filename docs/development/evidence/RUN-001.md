# RUN-001 抽取运行服务接口与所有权

## 基线

- 仓库：`basework`，日期 2026-09-12，工作树含本会话此前任务的未提交改动（用户未授权 commit）。
- 前置：CFG-003 已完成（资源归属与逆序释放）。

## 变更

**internal/runtime/service.go**（新增包）：

- 最小契约 `Service`：`Start(ctx, input)`（处理一条输入直到回合结束）、`Cancel(runID)`（取消进行中的运行，幂等返回 bool）、`Session()`（绑定会话信息）、`Subscribe()`（订阅运行事件流）、`Close()`（幂等释放）。
- 事件模型 `RunEvent`（started/finished）+ `Subscription`：全量事件流，单订阅者按发布顺序送达；容量 256 非阻塞投递，慢消费者丢事件而不阻塞运行主链路。按 runID 的有序子流、事件排序与取消语义的完整规则属 RUN-002。
- `LocalService` 进程内实现：不依赖 Bubble Tea、不监听网络端口（进程内服务边界，不是 server）。`Cancel` 作用于 Start 内部的运行级 context（从另一 goroutine 可取消同步运行的回合）。
- **所有权书面化**（包注释 + 字段注释）：Service 拥有 Agent 生命周期（Close 释放）；拥有后台任务管理器关闭职责（Close 先结束后台任务再关 Agent）；会话存储目录由产品层创建传入，Service 只持有运行期引用；Subscription 归调用方，退订/关闭竞争用 `closeOnce` 保证通道只关一次。
- `compile-time` 断言 `var _ Service = (*LocalService)(nil)`。

**cmd/basework/runtime.go**（适配）：

- `runtimeAgent` 保留 `sess`/`sessionID`/`jobManager` 引用（原先是无名局部变量，组装完即丢）。
- 新增 `(*runtimeAgent).Service()`：懒构造（`sync.Once`）并幂等返回 `intruntime.LocalService`，把已组装的 Agent/会话/任务管理器收拢进服务契约。
- agent.go/tui.go 的现有输入/输出路径**零改动**：`newRuntimeAgent` 签名不变，Service 是纯增量视图。完整的 CLI/TUI 统一接入是 RUN-003。

**测试**：`internal/runtime/service_test.go`（7 条：缺 Agent 构造失败、事件有序生命周期、错误透传 Run 与事件、取消进行中运行 + 幂等、会话绑定与无会话 nil、Close 幂等并释放 Agent 且 Start 报 ErrClosed、退订后不投递）；`cmd/basework/facts_test.go` 增 1 条（适配器幂等、会话绑定）。

## 变更

**pkg/session/facts.go**（新增）：

- `WorkspaceFacts`：跨会话持久化事实投影，与 `FileTracker`（会话内内存态）分工明确，不重复建模型。诊断信息刻意不入模型——`lsp_diagnostics` 是一次性查询而非发生事实，固化会漂移。
- `WorkspaceID(root)`：解析软链后取绝对路径 SHA-256 前 16 hex；同目录不同访问方式同 ID，不同目录天然隔离。
- 四类事实：`file_read`/`file_modified`/`file_reverted`/`command`；`Fact.Key` 去重键（`FileFactKey`/`CommandFactKey`——命令按 job id 去重，跨重启不重复累计）；`Add` 幂等（同键不新增、不刷新 `FirstSeen`）；`List` 按 (Kind, Key) 稳定排序。
- 持久化：`Save/LoadWorkspaceFacts`（`<dir>/facts/<workspace_id>.json`，临时文件 + rename 原子替换）。版本信封 `FactsSchemaVersion=1`：可读 v0 裸数组（无信封旧格式，按当前规则重建去重键）；`version > 1` 报 `ErrFactsTooNew` 拒绝解析；信封 `workspace_id` 与请求不符报错（防误读他人工作区）。
- `FoldFileEdited`：把 `file.edited` 事件折叠进事实集合；preview/冲突/未尝试不产生事实（「看过」不是「改过」）；折叠幂等，重复投影结果不变。

**归属戳（工作区隔离的关键）**：

- `FileEditedData` 增可选 `workspace_id`（兼容变更，按 migrate.go 规则不递增 SchemaVersion）；`edit_files` 工具发事件前用 `session.WorkspaceID(t.WorkDir)` 打戳。
- `jobs.Record`/`jobs.Job`/`jobs.Options` 增可选 `WorkspaceID`；runtime 构造 Manager 时注入当前工作区。
- **CLI 场景抓到真问题**：首版 `facts show` 把全局日志里所有事实归给当前 cwd，A 工作区能看到 B 工作区的编辑——隔离失效。修复后：带戳记录只进所属工作区视图；无戳旧数据显示来源「未归属(旧数据)」，不冒充当前工作区。

**cmd/basework/facts.go**（新增）：`basework facts show` 只读聚合视图——折叠任务日志（`AllHistory`，按归属过滤）与最近会话的编辑事件（`FirstSeen` 取事件 `CreatedAt`，单条损坏跳过告警）。CLI 不写事实文件；持久化写入留给运行时链路（CTX-003 接线）。

**测试**：`pkg/session/facts_test.go`（10 条：隔离与稳定、去重与 FirstSeen 保持、无键拒绝、排序、往返、缺文件空集、拒绝未来版本、拒绝他人工作区、v0 可读、折叠幂等）；`cmd/basework/facts_test.go`（2 条：编辑事件归属过滤、任务日志归属过滤与未归属标记）。

## 验证

- 任务卡针对性验证：`go test -tags "sqlite memory" ./pkg/session ./internal/tools -count=1` → PASS（连同受波及的 `./internal/jobs ./cmd/basework` 一起跑，四包 ok）。
- race：`go test -tags "sqlite memory" -race ./pkg/session ./cmd/basework` → PASS。
- `GOOS=windows` / `GOOS=linux go build ./...` → 通过；gofmt 干净。
- 全量双模式测试：默认模式与带 tag 模式（结果见末尾执行记录；均含本轮新增包）。
- CLI 人工场景（隔离 HOME，真实二进制）：
  1. ws-a `facts show`：重复提交的同一文件去重为 1 条 modified；冲突文件不产生事实；撤销产生 reverted；日志中重复 started 的同一 job 去重为 1 条命令事实。
  2. ws-b `facts show`：A 工作区的编辑不出现（归属过滤生效）；无戳旧数据显示「未归属(旧数据)」。
  3. ws-a 重复查看：条数不变（重复投影幂等）。
- 覆盖边界：`SaveWorkspaceFacts` 的运行时调用链路（折叠落盘）属 CTX-003「重启与压缩后的项目恢复」，本任务只交付模型与 CLI 只读视图；`file_read` 事实的来源折叠（read 工具事件）未实现——读取事件量大且价值低，按需在 CTX-002 预算模型中再决定是否纳入。

## 结论

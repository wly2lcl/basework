## 变更

**internal/runtime/service.go**（演进 RUN-001 实现）：

1. **持久化事件 vs 瞬时 UI 事件**（包注释明确）：`file.edited`/`turn.*` 等由 agent 与工具层写进会话存储、可跨进程重放，是事实来源；本包 `RunEvent`（run.started/run.finished）只在场观察、不落盘不重放——错过即错过，可靠性要求刻意低于事实。
2. **订阅缓冲与慢消费者策略**：`LocalDeps.EventBuffer`（<=0 默认 256）配置每个订阅者的有界通道；发布非阻塞，缓冲满丢弃并递增 `Subscription.Dropped()` 计数（观察窗口有缺口可被检测，调用方可重查会话存储补齐事实）。**无界队列被排除**：通道容量即配置值。
3. **同会话并发请求**：明确为**串行排队，不拒绝也不并发**（`runsMu` 贯穿 HandleMessage）。并发写同一会话会事件交错、投影混乱；排队符合交互式预期。Cancel/Subscribe 不取 runsMu，不会被运行卡住。
4. **关闭语义**：Close 取消所有进行中的运行（`cancels` 表整体迁移并触发）→ Start 调用方以 context.Canceled 返回；随后关闭全部订阅者通道（唤醒等待方）；jobs 关闭与 Agent 释放次序不变（先任务后 Agent）。
5. **取消目标隔离**：Cancel 只触发目标 run 的运行级 context；排队中的后续运行与新运行使用各自 ctx，不受影响。

**中断结果持久化**：取消导致的回合失败由 pkg/agent 既有机制持久化为 `turn.failed` 事件（`pkg/agent/loop.go` 事件写入路径，非本任务新增）；后台任务的取消/中断由 JOB-004 的 jobs 日志归并 `interrupted`。服务层不重复持久化瞬时 RunEvent。

**测试**（`internal/runtime/service_test.go` 新增 4 条 + 辅助）：

- `TestStart_SerializesSameSessionRuns`：run1 阻塞时启动 run2，事件序列必须 finished(run1) → started(run2)——串行化与顺序稳定。
- `TestCancel_NextRunUnaffected`：取消 run1 后 run2 正常完成——取消目标不影响后续运行。
- `TestClose_DuringRunCancelsRunningAndWakesSubscriber`：Close 使进行中运行以 context.Canceled 收场、订阅通道关闭、后续 Start 报 ErrClosed——取消/关闭/新建交错时序。
- `TestSubscription_DroppedCount`：缓冲满丢弃计数、通道容量等于配置值——无界队列排除。

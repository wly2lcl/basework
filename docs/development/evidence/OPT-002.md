# OPT-002 验证记录：长会话与长任务性能基线

## 基线

命令（固定三次样本、显式 benchmark、`-benchmem`）：

```text
GOCACHE=/private/tmp/basework-gocache go test -tags 'sqlite memory' ./tests/benchmark \
  -run '^$' -bench 'Benchmark(JSONLAppendEvents|JSONLProjectEvents|FactsSummaryRead|JobsHistoryList|TUIInputTransition)' \
  -benchmem -benchtime=1x -count=3 -timeout=10m
```

原始输出随仓库保存于 [`OPT-002-bench-2026-09-15.txt`](OPT-002-bench-2026-09-15.txt)。环境为 `darwin/arm64`、Apple M3、Go 1.26.0；样本不含网络模型等待。

固定规模覆盖：JSONL 追加/投影 100、1000、10000 事件；事实摘要 100、1000、10000 条；job 历史列表 100、1000、10000 条；TUI 输入状态转换。现有 `pkg/session` SQLite、压缩、流式、token 与工具基准继续保留。

## 验证

观察结果（取三次样本范围）：

- JSONL 追加：100 事件约 94–229 ms；1000 事件约 2.25–5.19 s；10000 事件约 112–130 s，约 8.0 GB 分配。当前逐条原子重写是明确的 O(n²) 候选瓶颈。
- JSONL 投影：10000 事件约 61–78 ms，约 37 MB 分配。
- 事实摘要：10000 条约 2.2–2.9 ms，约 1.99 MB 分配。
- job 列表：10000 条约 24–25 ms，约 7.36 MB 分配。
- TUI 输入状态转换：首轮约 1.0 ms，热轮约 12–16 µs，约 5.6 KB 分配。

## 变更

新增 `tests/benchmark/long_session_bench_test.go`，覆盖 JSONL、事实摘要、job 历史和 TUI 输入状态转换，并保存原始输出。

## 剩余与交接

本项完成的是可重复基线与证据，不直接重写存储。后续优化验收目标应先由这些数据拆出：追加改为增量日志/批量提交后，10000 事件追加应显著低于当前 100 秒级；兼容旧 JSONL、崩溃恢复和跨进程锁必须保留。

## 结论

性能基线完成，O(n²) JSONL 追加已被数据确认并转为后续优化候选；当前不把未经实现的存储优化写成完成。

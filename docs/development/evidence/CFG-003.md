# CFG-003 注册资源归属与逆序释放

## 基线

- 看板：前置 BASE-001 已完成。
- 注册资源盘点（任务卡步骤 1）：
  - **builtin 包级全局**（核心缺口）：`globalPathChecker` / `globalTimeoutConfig` / `globalEventBus`，由 `SetPathChecker` / `SetTimeoutConfig` / `SetEventBus` 写入，`bash`/`read`/`write`/`edit` 四个工具在 Execute 路径消费。进程内所有实例共享，后设置者覆盖先设置者——两个配置不同的 Agent（多 workspace 嵌入、主/子代理异配）会互相覆盖行为。三个注入点已由 `tests/arch_test.go` 白名单登记。
  - **产品运行时资源**：LSP manager（`Stop`）、MCP manager（`Close`）、后台 job 管理器（`runtimeJobCleanup`：`CloseOwner`+`Close`）、权限持久化（`permissionChecker.Cleanups`）。释放由 `runtimeCleanupPlugin` 承担（逆序）。
  - **agent 插件生命周期**：`pkg/agent` 已有「Initialize 部分失败 → 逆序 Shutdown 已初始化的插件」回滚与 `Close` 逆序关闭，且 `closed` 标志防重复（`pkg/agent/loop.go`）。
- 新发现的缺口：**`agent.New` 失败路径泄漏**。`newRuntimeAgent` 在调用 `agent.New` 之前就启动了 LSP/MCP 子进程、job 管理器、权限持久化；`agent.New` 返回错误时直接 return，这些资源没有任何人释放。
- `runtimeCleanupPlugin.Shutdown` 无幂等保护（重复调用会重复释放）。

## 变更

新增文件：

- `pkg/tool/builtin/runtime.go`：实例级运行时注入。
  - `Runtime` 结构体：`PathChecker` / `Timeout *TimeoutConfig` / `EventBus` 三个可选字段。
  - 解析顺序**实例字段 → 包级全局 → 内置默认**：注入的字段优先生效；未注入的回落全局；两者皆无回落内置默认。旧嵌入入口（`Set*` + 不带实例配置的工具）行为完全不变。
  - `AllWithRuntime(rt)`：构造全部内置工具并注入实例 Runtime（`All()` 保持不带实例配置，兼容旧路径）。
  - `WithTimeoutBus(ctx, name, timeout, bus)`：`WithTimeout` 的实例级版本；`WithTimeout` 改为委托到它（bus = 全局），行为不变。
- `pkg/tool/builtin/runtime_test.go`：4 条测试——实例检查器优先且全局变化不影响已注入实例（互不影响是核心断言）、实例超时优先于全局、两个实例的事件 bus 互不串扰（真实定时器触发验证）、`AllWithRuntime` 注入到全部支持实例的工具且注入的检查器在 Execute 路径真实生效。
- `cmd/basework/resources.go`：`runtimeResourceScope`——运行时资源的统一归属。
  - `Register(name, fn)`：创建时登记（带名字，释放失败日志可定位）。
  - `Close()`：**逆序**释放；**幂等**（重复调用为空操作）；单个失败不阻断其余（全部执行完返回第一个错误）——跳过剩余清理等于把泄漏扩大化。
  - 关闭后 Register 被拒绝并告警（创建于关闭之后的资源无人能释放，拒绝静默吞掉）。
  - `newRuntimeResourcePlugin(scope)`：scope 交给 agent 生命周期（`Initialize` 空操作，`Shutdown` = `scope.Close`）。
- `cmd/basework/resources_test.go`：6 条测试——逆序、幂等双重 Close、失败不跳过剩余、多实例隔离、插件 Shutdown 转发且幂等、关闭后注册被拒。

修改文件：

- `pkg/tool/builtin/bash.go` / `read.go` / `write.go` / `edit.go`：四个工具增 `Runtime *Runtime` 字段，Execute 路径的全局消费点全部改为 `resolve*()` 解析（超时事件发布改走 `WithTimeoutBus`）。
- `pkg/tool/builtin/timeout.go`：`WithTimeout` 委托到 `WithTimeoutBus`，行为不变。
- `cmd/basework/runtime.go`：
  - `newRuntimeAgent` 建 `runtimeResourceScope`，job 管理器、权限持久化、LSP、MCP 全部登记；**`agentOwned` 标记 + defer**：`agent.New` 失败时 scope 被 defer 释放（不遗留任何子进程/订阅），成功后所有权移交给 cleanup 插件；`agentOwned = true` 发生在 `agent.New` 返回无错之后。
  - `initializeRuntimeExtensions` 签名改为接收 scope，启动成功的扩展登记释放动作，启动失败的不登记不遗留。
  - `newBuiltinRuntime(cfg, pathChecker)`：从配置构造实例 Runtime（Overrides 拷贝一份，避免 config Mutate 换 map 后工具跟着漂移）；EventBus 留空回落全局（产品超时事件消费走 agent 层观测总线，builtin 级 bus 维持「未设置即不发布」的既有行为）。
  - `baseTools(cfg, rt)` / `runtimeSubAgentTools` / `readonlyRuntimeTools` 线程化实例 Runtime——主代理与子代理都拿到实例注入。
  - 旧的 `runtimeCleanupPlugin(cleanups...)` 三函数删除，由 resources.go 取代。
- `cmd/basework/runtime_test.go`：调用点适配。
- `docs/reference/pkg/tool/builtin.md`：注入点文档改为「实例级（推荐）+ 包级（兼容）」双轨说明，Known Limitations 相应更新。

关键决策：

- 不强改公开 `Plugin` 接口：scope 是产品适配层（任务卡步骤 2 的产品路线），插件接口保持 Initialize/Shutdown 不变，不承诺热卸载。
- 子代理与主代理共用同一份 `builtinRuntime`（同一进程同一配置）；跨配置隔离的价值在多 Agent 嵌入场景，由实例注入直接满足。

## 剩余与交接

- `SetEventBus` 的产品路径仍为「未设置即不发布」超时事件：产品的超时事件消费在 agent 层观测总线（`internal/observability`），builtin 级 bus 是给嵌入方的注入点。若产品未来要消费 `tool.timeout`，接入点已就绪（实例 Runtime.EventBus）。
- 内嵌库用户若同时使用 `Set*` 全局与实例注入，实例注入赢——文档已写明解析顺序，旧代码不需要任何改动。
- RUN-001（抽取运行服务接口与所有权）依赖本任务：scope 的归属模型可直接复用为运行服务接口的资源管理原语。
- 真实模型凭证不可用与本任务无关：资源释放路径不依赖 provider 连接。

## 结论

CFG-003 完成。builtin 的三个包级全局注入点获得实例级替代（`Runtime` + `AllWithRuntime`），旧入口完全兼容；产品运行时的全部可释放资源（LSP/MCP/job/权限持久化）归入 `runtimeResourceScope`，装配失败逆序释放、正常运行由插件接管、双重释放安全。一个实例的关闭/配置不再影响另一个；失败注册不遗留资源。任务卡口径的 race 验证与全部 28 项门禁命令通过。

# JOB-002 验证记录：增量输出与文件溢出

## 基线

- 起点 HEAD：`935fde1`；工作树含 BASE-001 / REL-001 / REL-002 / REL-004 / JOB-001 / EDIT-001 的未提交改动。
- 环境：macOS 26.6.2 arm64 / go1.26.0 / APFS（`t.TempDir()` 落在 `/var/folders/...`）。
- 相关既有实现核对结果：
  - `internal/jobs/jobs.go` 只做状态与归属；`run` 里执行体签名是 `Runner func(ctx) (int, error)`，
    **没有任何输出承接端**，注释里明确写「输出分页留给后续任务」。
  - `internal/tools/background.go` 里 `cmd.Stdout = io.Discard`、`cmd.Stderr = io.Discard`——
    后台命令的输出**被直接丢弃**，不是"存在但没暴露"。
  - 同步 bash（`pkg/tool/builtin/bash.go`）另有一套输出处理：内存拼接并硬截断到 100KB
    （`maxOutputSize`），没有溢出文件、没有分页偏移、没有保留期。两套口径不能复用：
    同步路径按"一次返回"设计，后台路径必须按"多次分页读取"设计。
  - `pkg/session/` 里没有输出相关的持久化事件（持久化属 JOB-004）。
- 因此本任务的起点是"输出被丢弃"，需要从零建立承接、配额、溢出、分页与保留期。

## 变更

### 新增 `internal/jobs/output.go`

- **两条配额界线**，而不是一条：
  - `MemoryLimit`（默认 256 KiB/流）——驻留内存上限，越过即落盘；
  - `MaxBytes`（默认 64 MiB/流）——内存+文件的总存储上限，越过即丢弃尾部。
  只留内存会被一条 `yes` 撑爆；全都写文件会让每条 10 字节的命令都产生 inode 与系统调用。
- **`Write` 永远返回 `(len(p), nil)`**：配额丢弃与溢出写失败都不表现为写入错误。
  理由是对子进程返回 EPIPE 会把它打死，而"输出太多"不该表现为"命令失败"。
  真实损失通过 `DropReason` / `DroppedBytes` 出现在每一次分页读取里，不会被悄悄抹掉。
- **丢弃而非报错的代价被显式记录**：`Truncated` / `DroppedBytes` / `DropReason` 三个字段
  出现在每个 `OutputPage` 与 job 终态快照上（`OutputTruncated`）。
- **UTF-8 切点**：`alignCut` 默认**回退**到最近的 rune 起点。回退而非前扩是刻意的——
  回退时那几个字节尚未返回，下一页会重新读到，既不漏也不重；前扩则会与"单次返回不超过
  limit"的承诺冲突。当 `limit` 小到连一个 rune 都放不下时，**只在这种情形下**向前扩到
  一个完整 rune，否则调用方会拿到空页原地打转。非法 UTF-8（二进制输出）也能终止：
  `utf8.RuneStart` 对非续字节恒为真，循环必然收敛。
- **跨内存/文件边界的读取**：`sliceLocked` 处理 offset 落在内存区、文件区、以及跨边界三种情形，
  拼接后统一对齐，因此分页边界与溢出位置无关。
- **私有文件**：目录 `0700`、文件 `0600`，用 `O_RDWR`（不是 `O_WRONLY`——只写句柄上
  `ReadAt` 会得到 `EBADF`，这是实现过程中真实踩到的失败）。
- **owner 不能穿越目录**：目录名取 owner 的 SHA-256 前 8 字节十六进制。直接拼 owner
  会被 `../` 写到输出根目录之外。
- **保留期与清理**：`Retention`（默认 24h）到期后读取返回 `ErrOutputExpired` 并带上
  `ExpiresAt`；`CleanupOutputs()` 只删过期的文件（删未过期的会让"分页不漏字节"失效），
  `Close()` 取消全部 job → 等执行体返回 → 关文件 → 删文件。顺序不能反：
  先删文件再等执行体，正在写的 sink 会往已删除的 inode 里写，结果是"命令成功了但输出丢了"。
- **可注入的 `SpillOpener` / `SpillFile`**：磁盘满与写到一半失败这两条验收，
  没有注入点就只能靠祈祷。
- 过期判断排在"已关闭"判断之前：清理会把 sink 置为已关闭，但调用方需要知道的是
  "过期了"，而不是内部状态变了。

### 修改 `internal/jobs/jobs.go`

- 新增 `SinkRunner func(ctx, stdout, stderr io.Writer) (int, error)` 与
  `Manager.StartWithOutput`。**`Start` 保持不变**，内部包一层空 writer 后走同一条路径。
  这是本任务唯一的产品 API 增补，属验收必需（不给出写入端就无法承接输出），
  在"范围外"条款下逐条说明而没有拆卡。
- `settle` 在**Manager 锁之外**取输出的 `stats()`（sink 有自己的锁，两把锁不嵌套持有），
  再在锁内一次性写入快照：`StdoutBytes` / `StderrBytes` / `OutputTruncated` / `OutputRefs`。
- `ReadOutput(owner, id, stream, offset, limit)`：越权与不存在返回**同一个** `ErrNotFound`，
  与 `Get`/`Cancel` 口径一致；未知流名返回 `ErrBadStream`（不会被当成 stdout），
  负偏移返回 `ErrBadOffset`。
- `Close()` 语义扩展为"取消 + 等待 + 清理"，幂等。
- `Manager.OutputDir()` 暴露溢出根目录，供产品层生成可检索引用。

### 修改 `internal/tools/background.go`

- `cmd.Stdout/Stderr` 从 `io.Discard` 改为 Manager 提供的写入端；
  权限入口顺序（黑名单 → 路径检查 → 启动）**未动**。
- `JobHandle` 增 `output_dir` 字段（溢出根目录），句柄仍是 `Result.Content` 里的 JSON，
  `pkg/tool` 接口未变（`git status --short pkg/tool/` 为空）。
- 代码注释里的覆盖边界同步更新：输出承接归 JOB-002，进程树清理归 JOB-003，
  注册工具与重启恢复归 JOB-004。

## 验证

## 剩余与交接

- **进程树清理（JOB-003）**：仍然只有 `exec.CommandContext` 杀直接子进程，孙进程不会被回收。
  取消/超时后可能留下孤儿进程，这是 JOB-003 的范围。本任务没有顺手实现。
- **注册成模型可调用工具（JOB-004）**：`ReadOutput` 目前只有内部 API 与测试使用，
  模型还不能调用"读 job 输出"。JOB-004 负责注册查询/输出/取消工具并沿用权限。
- **持久化（JOB-004）**：`OutputRefs` 只是内存中的路径；重启后 job 与输出引用全部丢失。
  重新加载时应把无法接管的运行中任务标为 `interrupted`。
- **产品组装未接线**：`BackgroundBashTool` 仍未注册进 `cmd/basework/runtime.go` 的工具表。
- **默认输出根目录**：`os.UserCacheDir()/basework/job-output`（不可用时退到临时目录）。
  这属于"应用私有目录"而非"用户数据目录"，尚未加入任何清理计划任务；
  当前只依赖保留期读取判定与 `Close`/`CleanupOutputs` 显式调用。
- **保留期到期不会自动修剪**：`CleanupOutputs` 需要被调用方定期调用（JOB-004 的
  owner 关闭清理应带上它）。没有后台定时器。
- **未验证范围**：Windows 上没有 `0700/0600` 语义（Go 会按平台映射），跨平台文件权限
  需在 SHIP-002 的实机上复核；本机只验证了 macOS APFS。

## 结论

验收项逐条对照：

| 验收条件 | 结果 | 依据 |
|---|---|---|
| 大输出不无限占内存 | 通过 | 双配额（内存 + 总存储）；`TestOutput_LargeVolumeStaysInMemoryBudget` 断言驻留内存恰为上限、溢出文件恰为余量；`TestBackgroundBash_LargeOutputSpillsToPrivateFile` 用真实子进程 200 KB 输出复现同一结论 |
| 分页不会漏/重复字节且 UTF-8 边界可处理 | 通过 | 回退式 rune 对齐 + `NextOffset` 严格由返回长度导出；`TestOutput_PaginationExactBytes`（7 种页大小逐字节比对）、`TestOutput_UTF8BoundaryNeverSplitsRune`、`TestOutput_PageGrowsToFitOneRune`、`TestAlignCut`、`TestOutput_OffsetBeyondEndIsEOF` |
| 越权读取被拒 | 通过 | 与 `Get`/`Cancel` 同一口径：越权与不存在返回同一 `ErrNotFound`；`TestOutput_UnauthorizedReadRejected`、`TestBackgroundBash_OtherSessionCannotReadOutput` |
| 磁盘满/输出过期有明确说明 | 通过 | 写失败降级为丢弃并记 `DropReason`，job 不因此判失败；过期返回 `ErrOutputExpired` + `ExpiresAt` + `Expired`；`TestOutput_SpillOpenFailureDegrades`、`TestOutput_SpillWriteFailureMidway`、`TestOutput_ExpiryAndCleanup` |
| 超量输出写私有文件并给可检索引用 | 通过 | `0600` 文件 + `Job.OutputRefs` / `JobHandle.output_dir`；`TestBackgroundBash_LargeOutputSpillsToPrivateFile`（权限位与路径包含关系均断言） |
| 输出保留期与关闭文件清理 | 通过 | `Retention` + `CleanupOutputs` + `Close`（取消→等待→关→删）；`TestOutput_ExpiryAndCleanup`、`TestOutput_CloseRemovesFiles` |

针对性与全量验证（含 `-race`）通过，2 个测试文件共 33 条用例覆盖全部验收条件。
未实现的部分（进程树清理、工具注册、持久化、跨平台权限）已在"剩余与交接"逐条写明，
未以"编译通过"或"mock 通过"冒充完成。

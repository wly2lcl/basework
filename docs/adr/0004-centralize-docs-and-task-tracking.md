# ADR 0004: 集中文档与单源任务进度

- Status: Accepted
- Date: 2026-09-12
- Supersedes: ADR 0003 中的根目录正文位置及包内 README 布局；单一权威原则继续有效

## 背景

用户要求统一根目录与 docs 的文档，并让能力较弱的 AI 可以接续开发、让人观察进度。旧 TASKS 超过 2600 行，历史完成标签与未勾选验收并存；设计分册、状态页与路线图也重复未来规划。

## 决定

- 根目录只留 README 导航；正文、包契约、社区文档统一在 docs。许可文件保留原位置，GitHub Issue/PR 模板保留平台要求的 `.github/` 位置，AGENTS 执行指令例外。
- 每个实际 pkg Go 包对应 `docs/reference/pkg/<包路径>.md`，检查五节：用途、配置、扩展点、Model Experience、Known Limitations。
- `docs/TASKS.md` 唯一维护状态与依赖；任务卡维护内容，证据文件维护运行结果；progress 现场计算数量。
- 旧文档整体归档并标记过时，不以删除历史换取整洁；旧 Phase 不再统计新进度。
- 现状、计划、验证分开表达；没有证据不得从“已写代码”推断“产品已完成”。

## 后果

读者从一个入口找到现状、计划与下一项。检查器同步拦截根目录正文回流、包内 README 回流、任务依赖错误与完成缺证据。

根目录旧路径与 pkg README 的外部书签会失效；仓库内链接统一迁移，不留复制正文。GitHub 对部分社区文件在 docs 下的自动识别可能不同，根 README 提供明确导航。无需引入另一套项目管理服务。

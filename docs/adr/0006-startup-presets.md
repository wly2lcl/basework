# ADR 0006: 启动预设的覆盖次序与数组替换规则

- Status: Accepted
- Date: 2026-09-12
- Supersedes: —

## 背景

产品需要一组「可组合的启动预设」（CFG-002）：一条命令把运行时切到只读或完整
编码能力。预设一旦存在，就必须回答两个问题，否则每个调用点都会自行发明答案：

1. **预设与配置文件、命令行、环境变量的覆盖次序**——同一字段多处指定时谁赢？
2. **数组字段的合并规则**——预设定义的工具白名单与配置文件里已有的列表是
   拼接还是替换？

不这么做会怎样：`config explain` 展示的有效值与 runtime 实际使用值分叉
（这正是 CFG-001 要消除的信任裂缝），以及「只读预设」可能因为列表拼接而
悄悄混进写/执行工具。

考虑过的替代方案：**数组做并集合并**——被否决。并集意味着配置文件里遗留的
一个 `bash` 就能击穿只读预设，安全语义变成「最少受信来源决定」，无法审计。

## 决定

我们决定采用「**后位整体覆盖前位；数组一律整体替换，永不并集**」：

```
内置默认 → 配置文件（含其中的 preset 字段，加载时立即展开） → 命令行 --preset → 环境变量（仅 provider 等既有项，不新增预设相关变量）
```

- **次序**：命令行 `--preset` 晚于配置文件 `preset` 字段生效，后位覆盖前位。
  两者同时指定且**值不同**视为冲突，启动直接报错（不是静默择一）；值相同则合法。
- **数组替换**：预设展开时对自己拥有的数组字段（当前仅 `tools.allowed`）
  **整体替换**既有值，不做并集、不做差集。配置文件想自定义白名单就不要同时
  声明会覆盖它的预设。
- **冲突判定**：配置文件已显式给出 `tools.allowed` 且又声明了会定义 `tools.allowed`
  的预设 → 报错；未知预设名 → 报错。其余字段预设直接覆盖，不视为冲突
  （预设就是「一揽子覆盖」的语义）。
- **未指定时旧行为**：`preset` 未设置（且无 `--preset`）时，不新增任何覆盖
  步骤，行为与 CFG-002 之前完全一致。
- **只读硬保证**：`readonly` 预设展开后在运行入口做一次白名单子集校验，
  任何写/执行类工具出现在最终工具表即启动失败——替换规则靠机制兜底，
  不靠「写配置的人小心」。

## 后果

- 正面：`config explain` 可以按同一套次序复现有效值；只读预设的边界是
  机械可验证的；数组语义只有一条规则，无合并歧义。
- 代价：数组不能「部分追加」——用户想加一个工具必须写全量列表。对配置
  规模而言这是可接受的负担。
- 后续：新增预设类型时必须同时更新 `config explain` 的展示与本 ADR 的
  预设清单；`tools.allowed` 的通配（前缀 `*`）语义若扩展，需先改本 ADR。
